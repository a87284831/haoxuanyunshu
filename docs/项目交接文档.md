## 1. 项目是什么

物业公司内部一体化管理系统。**薪酬核算是核心**（项目员工/案场/管理/总部四类人员），集成：
考勤上传与符号库、钉钉花名册同步、个税独立计税、五险一金、绩效考评、财务台账、

技术栈一句话：Laravel 11 + Vue3 SPA（base `/app/`）+ MySQL 单库 `payroll`（51+ 表）+ 钉钉开放平台。
当前状态：**已上线运行**（2026-09-30 首部署），主干 `main`，本地 = GitHub = 生产 三端一致。

## 5. 运维 Runbook

### 5.1 部署（唯一正规路径）

有现成 skill：`laravel-prod-deploy`（快照 → scp 整包 → chmod 755 → 重建 config/route 缓存 → 冒烟）。要点：

1. 本地测试全绿（phpunit + vitest + build）→ commit + push
2. 服务器侧先打快照（`/root/pre_deploy_*`）
3. 后端：scp 覆盖 PHP 文件 → `config:cache` + `route:cache` + reload php8.2-fpm（**restart 才能清 opcache 的场景用 restart**）
4. 前端：**必须** `deploy/deploy-frontend-full.sh` 整包同步（含空包自检 + 资源 200 校验 + 失败自动回滚）；deploy/ 被 gitignore 需 `git add -f`
5. 有迁移时 `migrate --force`，迁移先在本地和生产快照后执行
6. 冒烟：内外网 /app/ 200、/api/payroll 401、新 chunk 全 200、laravel.log 无新错误、代码标记自检（特征字符串命中）
7. 部署后把部署事实追加到《开发记录.md》

**禁止**：服务器上手改代码、服务器上 npm build、手动挑 chunk 上传、`rm -rf` 产物目录。

### 5.2 紧急事故处置（10-22 CPU 事故验证过的流程）

症状：网站白屏/无响应、SSH 超时，但 TCP 能连——**大概率 CPU 被占满**（进程拿不到时间片）。

1. 阿里云控制台 → **Workbench 网页终端**（不依赖 SSH 端口）
2. `top -c -b -n 1 | head -20` 定位高 CPU 进程
3. 应急恢复：`systemctl restart nginx php8.2-fpm`（不行再 restart mysql，最后 restart 整机）
4. 恢复后必须查根因：laravel.log、慢查询、cron 任务堆积（`ps aux | grep artisan`）
5. 已知根因已修：CACHE_STORE=database 锁失效致钉钉同步堆积——现在 .env 是 `CACHE_STORE=file` / `QUEUE_CONNECTION=sync`，**迁移新机时这两个值必须照搬**

### 5.3 常用生产命令


## 6. 绝对不能踩的坑（分类版）

### A. 薪酬口径类（动了就是动所有人的钱）

1. **符号字面漂移**：生产 symbols.json 曾是 'V' 而考勤用 '√'，精确匹配失败→全月出勤 0→工资全 0。
   已加别名容错（√∨Vv✓✔）和保存兼容性检查；任何符号改动都要全月回归。
2. **核算进行中不要在设置页切换绩效方式**：曾与核算脚本时序相撞，算出 quarterly ratio:0 绩效归 0。
3. **季度末无历史数据/无系数时绩效显式为 0 并挂错误标记**——设计行为不是 bug；年初提前录上年 Q4 系数。
4. **仅改单月个税会导致后续累计错误**：历史工资必须整段导入（35 列完整模板，精简模板明细空白）。
5. **重算只删当月行**（where year_month=$ym），不动归档往月；但改了往月数据后必须重算季度末月，季度结果才更新。
6. **0.01 差异/五险一金 round 顺序/逐月 round 再累加**是既定口径，禁止"顺手优化"（见第 2 节 #2）。
7. **归档行有快照保全**：重算删插后归档行金额恢复旧值；HTTP 层还有 409 二次确认。别绕开。
8. **数据获取失败/为空必须显式显示为空，禁止静默降级**（用户铁律，防算错钱）；薪资核算时有人工资获取失败必须提示。

### B. 部署/运维类（都出过事故）

9. **CPU 99.5% 事故（2026-10-22）**：CACHE_STORE=database 缓存损坏 → withoutOverlapping 锁失效 →
   钉钉同步进程堆积占满 CPU → 全站白屏 + SSH 失联。修复：flock 文件锁兜底（不依赖外部服务）+
   CACHE_STORE=file + QUEUE_CONNECTION=sync + CPU watchdog + 慢查询日志。**新机 .env 必须照搬这两项**。
10. **白屏事故①（10-21）**：手动挑 4 个改动 chunk 上传，漏了新主入口 index-Dew5XZlX.js → 404 白屏。
    **vite 构建全量重生成哈希文件，前端部署必须整包同步，严禁手动挑文件。**
11. **白屏事故②（10-21）**：部署脚本清理旧产物时产物清单为空 → `comm -23` 把服务器全部产物判旧删光。
    现脚本有空包自检+自动回滚；**不要绕过脚本手工 rsync/rm 产物目录**。
12. **本地服务不要用 `php artisan serve`**：`/app` 是目录，SPA 深链/刷新 404。
    固定用 `php -S 127.0.0.1:8910 -t public server_router.php`（"Failed to fetch" 先查端口进程还活着没）。
13. **迁移唯一索引名 ≤ 64 字符**（MySQL 限制，SQLite 不报错）：period_coefs 索引 65 字符曾在生产 migrate 中断。
14. **备份脚本 find -delete 必须加 -maxdepth 1**，否则递归删掉 monthly/ 长期快照。
15. **mysqldump 的 cnf 不能有 database= 行**，否则 dump 单库认证失败。
16. **tar 打包注意 Windows 编码**：中文文件名可能损坏→生产解压 404；用英文文件名或服务器侧打包。
17. **重算前核查全部考勤块 locked=1**：10-19 新沂春暖花开块 locked=0 致王帅山行丢失（binlog 找回）。
18. **部署脚本必须含 scp 上传步骤**：10-20 漏写 scp 致标记自检全 0 假失败。

20. **登录 500 事故（2026-10-25，"Server Error"）**：以 root 身份跑 `php artisan migrate/cache:clear/route:cache` 后，
    新生成的缓存文件属主变成 root，PHP-FPM 实际运行用户是 **www-data**（不是 www，宝塔默认是 www 本机已改）无法写入 →
    登录 `Cache::put` 触发 `file_put_contents` 失败 → Laravel 异常处理器尝试写 `laravel.log` 同样被拒 →
    **递归异常**，前端收到无堆栈的 500 "Server Error"，日志里**没有任何记录**（因为 log 都写不进去）。
    排查要点：开启 `APP_DEBUG=true` 后错误详情才能透出，看到 "Failed to open stream: Permission denied"
    指向 `storage/logs/laravel.log` 或 `storage/framework/cache/data/xx/yy/` 即为此问题。
    **修复**：`chown -R www-data:www-data storage bootstrap/cache` + `chmod -R 775`。
    **预防**：`deploy/deploy-frontend-full.sh` 和 `deploy/deploy-backend.sh` 末尾已固化权限重置；
    **后端 artisan 命令必须 `sudo -u www-data php artisan ...` 执行**（详见 deploy-backend.sh 注释）。
