## 一、项目概述

物业公司内部一体化管理系统。**薪酬核算是绝对核心**，其余模块（考勤、钉钉、人员、绩效、审批、采购、财务、维保、报表）都围绕它或相对独立。

- 单租户内部系统：约 73 名管理人员 + 17 个项目的一线员工，月度批量核算为主。
- 后端 Laravel 11（纯 API，`/api/*`），前端 Vue3 SPA（history 模式，base `/app/`）。
- 本地 SQLite 开发，生产 MySQL 单库（库名 `payroll`，51+ 张表，原采购/财务两库已并入）。
- 四种薪酬人员类型：`staff` 项目员工、`case` 案场人员、`manager` 管理人员、`hq` 总部人员。
- 三种绩效发放方式：`monthly` 月度绩效法、`quarterly` 分期兑现绩效法、`quarter_grade` 季度绩效法（**生产当前用法**）。
- 钉钉是人员档案的权威来源：花名册字段本地禁止编辑，只走定时全量同步 + 事件回调。

### 总体架构

```
浏览器 (Vue3 SPA, /app/)
   │  fetch /api/*  (Authorization: Bearer <token>)
   ▼
nginx ── try_files → public/index.php ── routes/api.php
                                            │
              ┌─────────────────────────────┼───────────────────────────┐
              ▼                             ▼                           ▼
      Http/Controllers/Api          Services（核算/规则/钉钉/表达式）   Finance/ Purchase/（handler 分发）
              │                             │
              ▼                             ▼
                     MySQL（生产）/ SQLite（本地）
                     legacy_json_snapshots 表（配置权威存储）+ data/*.json（镜像）
                     钉钉开放平台 API（花名册全量同步 / 事件回调）
```

### 一条工资的诞生路径（宏观数据流）

```
钉钉同步人员档案(payroll_staff) + 薪酬设置(calc_rules.json)
        │                              │
        ▼                              ▼
考勤 Excel 上传(payroll_attendance, 锁定后参与核算)
        │
        ▼
点「核算」→ PayrollWriteController::calculate* → PayrollCalculator::calculateGroup
        │  逐人 computeRow 算出应发/扣款/个税/实发，写入 payroll_results
        ▼
检查无误 → 归档(archived=1 锁定) → 导出 Excel / 工资条查询
        │
        └─ 有错 → 微调(payroll_adjust_logs 留痕) 或 解锁归档后重算
```

### 配置存储机制（全项目最容易误解的一点）

四类业务配置**不是** `.env`，是 JSON 文档：

| 配置 | 文件镜像 | 内容 |
|------|----------|------|
| `calc_rules` | `data/calc_rules.json` | 薪酬规则全集：公式、个税设置、缺卡阶梯、五险一金、补贴、pay_rules 绩效方式 |
| `symbols` | `data/symbols.json` | 考勤符号库（出勤/加班/请假/旷工等符号定义） |
| `settings` | `data/settings.json` | 公司信息等杂项 |
| `payslip_config` | `data/payslip_config.json` | 工资条显示列配置 |

- **权威存储是 MySQL 表 `legacy_json_snapshots`**（key 为主键），`data/` 目录只是镜像（`.env` 里 `LEGACY_DATA_PATH=../data`）。
- 写路径：`ConfigController::saveSnapshot` 用 `array_replace_recursive` 合并后双写（库+文件）。**副作用：删除某个键不会生效，旧键会残留**（已知问题 P1-2，无害但要注意）。
- 读路径：`CalcRules` 等服务类请求内单例缓存，改配置后同一请求内不会读到新值。

## 四、核心概念与数据模型

### 4.1 四类人员 与 四种工资表

| 人员类型 person_type | 中文 | 工资表（row_type） | 核算入口 | 绩效方式（生产现状） |
|---|---|---|---|---|
| `staff` | 项目员工 | `staff` | calc（按项目逐个） | monthly 月度系数（考勤行带入） |
| `case` | 案场人员 | `case` | calc-case（按月一批） | monthly |
| `manager` | 管理人员 | `manager` | calc-managers（按月一批） | **quarter_grade**（按档位：经理级季度型/主管专员月度型） |
| `hq` | 总部人员 | `hq` | calc-hq（按月一批） | **quarter_grade** |

关键约定：
- **管理人员 ≠ 总部人员**。`manager` 是"管理线"（各项目的管理岗），`hq` 是"物业公司总部"这个特殊项目下的人。代码里 `HQ_PROJECT = '物业公司总部'`（PayrollCalculator L60）。
- **分类按月判定**：`PayrollCalculator::categoryMap($ym)`（L79）读 `payroll_staff_person_type_log`，若某人的 `person_type_since` 晚于核算月末，则该月仍按 `staff` 算。**同一个人不同月份可以属于不同类别**（调动生效次月才换类）。
- 案场/管理没有自己的考勤项目块，考勤数据散落在各项目块里，靠**虚拟组**聚合：`ATT_VIRTUAL_GROUPS = ['__managers__' => ..., '__case__' => ...]`（L66）。

### 4.3 payroll_results.row_data 字段字典

`row_data` 是 JSON，**序列化后所有键恒存在**（没值是 `null`/`0`，所以测试断言用 `assertNull` 不用 `assertArrayNotHasKey`）。主要字段（真相以 `PayrollCalculator::computeRow` L509 组装数组为准）：

| 字段 | 含义 | 计算口径速查 |
|---|---|---|
| `h` | 应出勤天数 | 考勤 `req_attend`；缺失时按 `prorate_base` 规则（calendar 日历天 / required 应出勤）折算 |
| `actual` | 实际出勤（符号加总） | 符号库统计，别名容错 |
| `coef` | 月度绩效系数 | 考勤行读入，默认 1；季度型人员此值不参与 |
| `base` / `fixed` | 基本工资 / 固定月薪 | 来自当月生效的薪资段 |
| `base_pay` | 基本薪资（按出勤折算） | 逐段 `base × 段出勤 / H` 求和 |
| `perf_pay` | 绩效工资 | 月度型：`max(0, fixed−base) × coef × 段出勤/H`（试用段跳过）；季度型：季度末月一次发 |
| `base_pay_ref` / `perf_pay_ref` | 满勤基准值 | 微调缩放参照系 |
| `sick_pay` | 病假工资 | `病天 × 段基数 × 0.7 × 0.6 / H`（70% 基数再打 6 折） |
| `absent_fine` | 旷工扣款 | `段基本/H × (倍数−1) × 旷天`（倍数来自 calc_rules） |
| `miss_deduct` | 缺卡扣款 | 阶梯：前 3 次 ×30，之后 ×50（可配）；次数×10 与手填额**取大** |
| `late_deduct` | 迟到早退扣款 | 次数 ×10 与手填额取大 |
| `meal_sub`/`night_sub`/`title_sub` 等 | 各类补贴 | `mode=full` 全额 / `prorate`：`min(值, 值×actual/h)` |
| `pen`/`med`/`une`/`house`/`big` | 五险一金（养老/医疗/失业/公积金/大病） | **分项各自 round 再合计** |
| 专项附加扣除 6 项 | 子女教育/赡养老人等 | `specKeyMap` 按关键字匹配考勤列表头 |
| `gross` | 应发合计 | `DEFAULT_GROSS`（L36）定义的加项清单；`welfare`（已发福利/奖励）是加项 |
| `tax` | 本月个税 | 见 5.7 累计预扣 |
| `tax_diff` | 计税差异调整 | 公式外加减项，可正可负，本身不再计税 |
| `net` | 实发 | gross − 各项扣款 − tax；`welfare` 在 `DEFAULT_NET`（L55）里是**减项**（已发福利计税但不实发） |
| `perf_detail` | 绩效明细（季度型） | 含每季度逐月基数；出错时带 `error` 错误码 |
| `error` / `perf_error` | 显式失败标记 | 见 5.5 错误码；核算时该行变 danger 跳过入库 |

### 4.4 月份与周期口径约定

- `ym` 格式恒为 `YYYY-MM`，是所有表的时间主键组成部分。
- **季度末月 = 4、7、10、1 月**（`isQuarterEnd`）。季度区间映射 `quarterPeriod`：4 月→当年 Q1（01-03）、7 月→Q2、10 月→Q3、**1 月→上年 Q4（10-12，跨年）**。
- **半年度末月 = 7、1 月**（`isHalfYearEnd`），仅 quarterly 旧法用。
- 系数录入 UI 只在季度末月出现（前端 `payrollLogic.js` L88 同款判断，前后端各有一份，改了一边别忘了另一边）。
- 归档（`archived=1`）= 该月工资锁定，重算/微调/删月/重传考勤全部被拒，需先解锁。

## 五、薪酬核算（核心中的核心）

> 全部算法在 `app/Services/PayrollCalculator.php`（约 1431 行）。Controller 只做鉴权、参数、拦截，**不要在 Controller 里写计算逻辑**。

### 5.1 核算总入口与流程

四个 HTTP 入口（PayrollWriteController）：`calculate` L21（项目员工，按项目数组）、`calcManagers` L62、`calcCaseStaff` L89、`calcHq` L116。它们最终都进：

**`PayrollCalculator::calculate/calculateManagers/calculateCaseStaff/calculateHq`（L104-151）→ `calculateGroup`（L235，核算主体）**

`calculateGroup` 逐步流程（括号内为行号附近逻辑）：

1. **取符号库**（symbols），解析出勤/请假/旷工等符号定义。
2. **取已锁定的考勤块**（locked=true 才参与；未锁定的项目被跳过并计入 warnings）。
3. **取当月人员分类** `categoryMap($ym)`（L79）。
4. **逐人处理**：
   - 找考勤行 `findAttRow`（L421）：**优先按 `dingtalk_userid` 匹配 → 其次 `staff_id` → 最后姓名兜底**（旧数据没打标才用姓名）。
   - 口径A：月初之前已离职的人**不提示、直接跳过**（L286），不算缺考勤。
   - 在职且该有考勤但没有 → 标记 `no_attendance`（L265），**不动该人旧结果行**（不会删也不会写）。
   - **缺基数护栏** `hasMissingBase`（L439）：有出勤但 fixed 和 base 都为 0 → 标记 danger **跳过该人**（不产出工资行），防止 0 元工资静默入库。
5. **算钱** `computeRow`（L509），产出整行 row_data。
6. **汇总警告**：`net ≤ 0` 记 info 级 warning；`perf_error` 记 danger。
7. **入库**（关键，见 5.10）：`withCalcLock`（L479，MySQL `GET_LOCK` 命名锁）+ 事务：删当月旧行（**保留 archived 行的快照用于保全** L371-409）→ 新行 chunk(100) 批量插入 → 恢复归档标记。

**重算对归档行的保全逻辑**（L371-409，极易踩坑）：重算会先删再插，如果某行原来是 `archived=true`（历史导入或已归档），删除前会把旧行整个存下来，插入新行后**用旧行覆盖回去**——即归档行的金额永远不被重算改变。但注意：`PayrollWriteController::archivedCalcBlocker`（L278）在 HTTP 层先拦截：目标范围有归档行时首次请求返回 409 + 名单，前端弹确认，二次请求带确认参数才放行到 Calculator。

### 5.2 computeRow（L509）：一行工资怎么算出来的

输入：人员档案行、考勤行、符号统计、calc_rules。输出：row_data 数组。顺序大致：

1. **定应出勤 `h`**：优先考勤行 `req_attend`（手填优先）；缺失时按 `prorate_base` 配置折算（`calendar`=按日历天比例 / `required`=按应出勤比例），月中入职/离职会按在职天数折算。
2. **定系数 `coef`**：考勤行读入，默认 1。季度绩效法人员考勤行不允许带系数（上传时被 `guardQuarterCoef` 拦截，见考勤章）。
3. **薪资分段** `salarySegments`（L1211）：把当月按 `salary_history` 生效日切成若干段（见 5.4）。
4. **逐段累计**：
   - `basePay += base × 段出勤 / H`
   - `perfPay += max(0, fixed − base) × coef × 段出勤 / H`（**试用期段跳过绩效**）
   - 病假：`sickPay += 病天 × 段基数 × 0.7 × 0.6 / H`
   - 旷工：`absentFine += 段基本 / H × (倍数 − 1) × 旷天`（倍数在 calc_rules，注意 −1 是因为那一段基本工资本来就没发）
5. **缩放基准**：`scale = actual / symbolAttend`；`basePayRef`/`perfPayRef` 是满勤基准，供微调页"按比例缩放"用。
6. **补贴/扣款**：见 5.9。
7. **绩效（三种方式分支）**：见 5.5 / 5.6。
8. **五险一金 → 专项附加 → gross → 个税（5.7）→ net**。
9. **公式引擎兜底**：如果 calc_rules 配了自定义公式，`CalcRules::evaluate` 求值；**求值失败直接 throw，整个月核算中止**（不是跳过一个人，是全月中止），错误信息含员工姓名+表达式。

### 5.3 薪资分段 salarySegments（L1211）

- 数据源 `salary_history`：**逐日取"最后生效"的一段**（生效日 ≤ 当天的最新记录）。
- 相邻同参数段会合并，减少无意义分段。
- 试用期判定：`StaffStatus::isProbationOnDate`（L38），`planned_regular_date`（预计转正日）兜底；试用段不发绩效。
- `appendSalarySegment`（L1185）：若某人没有任何更早的薪资记录，自动补一条「入职定薪」基线段；同一生效日重复记录会去重。
- **为什么分段**：月中调薪时，调薪前后的 base/fixed 不同，必须按天数拆开算，否则全月按一个数算会错。

### 5.4 三种绩效发放方式（quarterly/quarter_grade/monthly）

分支在 computeRow 内的绩效段（L612-735 是季度部分）。由 `CalcRules::getPayRule(personType, payGrade)` 决定，返回 `cycle / mode / ratio / configured` 四元组。薪酬档位 `PAY_GRADES = ['专员级','主管级','经理级']`（CalcRules）。

| 方式 | 适用 | 算法 |
|---|---|---|
| `monthly` 月度绩效法 | 项目员工/案场；quarter_grade 下的主管级、专员级 | 每月 `max(0, fixed−base) × 当月 coef × 出勤比例`，coef 从考勤行读 |
| `quarter_grade` 季度绩效法（生产在用） | 管理/总部按档位 | **经理级=季度型**：季度中月份绩效=0，季度末月（4/7/10/1）发 `季度系数 × Σ(季度内每月绩效基数 × 该月perf_att/req_att)`，无比例无半年度；**主管/专员级=月度型**同 monthly |
| `quarterly` 分期兑现绩效法（旧） | 历史 | 季度末发 `Σ基数 × 季度系数 × quarter_ratio`（比例配置），7 月追加 H1 半年度比例 |

- quarter_grade 的季度系数**优先读 `payroll_period_coefs` 表**，同时兼容老数据主表 `row_data.coef`（迁移期双读）。
- **绩效基数来自 accumulatePeriodPerf（L1389）**：回头读季度内每个月已入库行的绩效基数，**逐月先 round 再累加**。
  ⚠️ 这就是著名的 **0.01 差异根因**：手工核算通常"加总后再 round"，系统"每月先 round 再加"，极端情况差 1 分钱。**已知问题，用户确认不修**。
- **显式失败原则**：缺系数 `missing_coef`、缺档位 `missing_pay_grade`、非法档位 `invalid_pay_grade`、缺规则 `missing_pay_rule`——行内标 `perf_error`，中文文案在 `PERF_ERROR_CN`（L42），核算结果该行不静默按 0 入库。

### 5.5 个税（L836-868）：累计预扣，独立计税

- **起算月 `taxStartMonth`** 两种模式（calc_rules 里 `cum_start` 配置）：
  - `jan`：max(入职月, 当年 1 月)
  - `prev_dec`：上年 12 月（**生产 2026-10-19 起用此口径**，为了把 2025-12 历史工资纳入累计）；12 月本身为窗口时只算自身。
- `monthNumber` = 从起算月到当月的月数（决定减除费用倍数）。
- **只累计本系统的数据**：读 `payroll_results` 里 `startMonth` 之后的历史行，累计收入与已扣税；系统外发过的工资不进来。
- 累计减除 `cumDeduction`：普通模式 `5000 × 月数`；"6 万模式"`= 60000`（一次性）。
- `cumTaxable = max(0, 累计收入 − 累计减除 − 累计社保 − 累计专项附加)`。
- `cumTax` = 7 级超额累进（年税率表按月换算；**超过最高档按最高档算**）。
- **本月税 = max(0, cumTax − 累计已扣税)**。可为 0，不为负。
- `tax_diff`（计税差异）是公式外手工加减项，**不计入税基**。

### 5.6 公式引擎：CalcRules + Expr

- `CalcRules.php`：读 calc_rules.json；`FORMULA_VAR_CN` 把中文变量名归一化成英文键（**保存公式时前端也必须做同一转换**，两边漂移会导致公式求值取不到变量）；`flag()` 解析各种布尔配置；`evaluate()` 支持主/备两条公式，主公式失败尝试备公式，`lastError` 记录原因。
- `Expr.php`（手写递归下降解析器，**不用 eval**，安全）：入口 `Expr::evaluate($expr, $vars)`（L23），支持 `+ − * / %`、括号、函数 `min/max/abs/round/floor/ceil/if`（L16 常量）。`parseExpr → parseTerm → parseFactor`（L81/92/105）三级优先级。
- 规则：**公式求值失败必须中止核算并报员工姓名+表达式，禁止静默按 0 计薪**（这是用户定的铁律，整个系统"显式失败"风格的来源）。

### 5.7 五险一金 / 专项附加 / 补贴扣款细节

- **五险一金**：养老 pen、医疗 med、失业 une、公积金 house、大病 big，**每个分项各自 round 后再加总**（不是加总后 round，和 0.01 差异同理的口径选择，改不得）。
- **专项附加扣除 6 项**：子女教育、继续教育、大病医疗、房贷利息、住房租金、赡养老人。`specKeyMap` 按**关键字匹配**考勤表头列名取值。
- **缺卡扣款** `missPunchAmount`（L1344）：阶梯计费——前 3 次每次 30，超出每次 50（金额可配）；**与手填的 `miss_deduct` 取大值**。
- **迟到早退**：次数 × 10 与手填额取大。
- **补贴（餐补等）**：`mode=full` 全额发；`mode=prorate` 按 `min(配置值, 配置值 × actual/h)` 折算。
- **`welfare`（已发福利/奖励）两面性**：在 `DEFAULT_GROSS`（L36）是**加项**（计入应发、参与计税），在 `DEFAULT_NET`（L55）是**减项**（钱已经发过了，实发里扣回来）。改这两份清单前务必想清楚计税 vs 实发的差异。

### 5.8 并发锁、事务与入库

- `withCalcLock`（L479）：MySQL `GET_LOCK` 命名锁，防止两个请求同时重算同一个月导致删插交错。**SQLite 本地环境没有 GET_LOCK，代码有兼容分支**，所以本地测不出锁的效果，别误以为没用就删了。
- 事务内：删当月范围旧行（archived 行先快照）→ chunk(100) 插新行 → 恢复归档快照。任何一步失败整体回滚。
- `DingtalkSyncCommand` 和审批流等其它写路径与核算无共享锁，但重算期间不要并行做考勤上传/删除（HTTP 层已有 locked/archived 拦截，双保险）。

### 5.9 归档 / 解锁（PayrollWriteController::archive L137）

- 归档 = 把范围内行 `archived` 置 1（L171）；解锁反之。
- **归档前置检查**：存在"薪资基数缺失"（有出勤但 fixed/base 均 0）或"绩效配置缺失"（perf_detail.error）时返回 409 `{need_confirm:true, blockers:[...]}`，前端列清单让用户确认，`force=true` 才放行并写 warning 日志。**解锁（locked=false）不做此检查**。
- 归档后的效果：不能微调（adjust L335 拦截）、不能整月删除（deleteMonth L203 拦截）、不能重传考勤（AttendanceController::upload L121 拦截）、重算被 archivedCalcBlocker 409 拦截。

### 5.10 微调（adjust L313 → recomputeDerived L921）

- 微调 = 归档前对单行手工改数字。每次微调写 `payroll_adjust_logs`（旧值→新值）。
- 改完触发 `recomputeDerived`（L921）：**按与 computeRow 完全相同的口径**重算派生项（gross/税/net），保证手工改了 base_pay 后税额自动跟上。
- 已归档行禁止微调（L335）。

### 5.11 历史工资导入（importHistory L425）

- 用途：把系统上线前的历史工资灌进 `payroll_results`，供个税累计和季度绩效基数查询。
- **35 列标准模板**（列名与系统导出一致，L475 起做精确列映射，也兼容别名）；`deptFromPath`（L768）从部门路径解析项目；`parseSheetMonth`（L780）从 sheet 名解析月份。
- 导入行直接 `archived = true`（L686/696）——**历史行不参与重算，重算也改不动它**（5.8 的保全机制）。
- 解析失败生成错误报告 Excel：`writeImportErrorReport`（L724）写临时文件，前端经 `errorReport`（L756）按 token 下载。
- 生产已导入：2025-12 管理 37 行 + 2026-01~07 管理 243 行（详见交接文档，这是 prev_dec 个税口径的数据基础）。

### 5.12 整月删除（deleteMonth L181）

- 按 `row_type` 范围删当月行；`applyRowTypeScope`（L252）控制四类表各自的作用域（如 manager 表排除总部项目）。
- **有归档行则整单拒绝**（L203-205），必须先解锁。

### 5.13 季度/半年度系数接口（PayrollController）

- `savePeriodCoef`（L491）保存系数到 `payroll_period_coefs`；`periodKeyToMonth`（L539）把 `2026-Q1` 这类键映射到季度末月；`listPeriodCoef`（L552）查询；`pendingPeriodCoef`（L578）列出"该录还没录"的系数（适配 quarter_grade）。
- 前端系数录入按钮只在季度末月（1/4/7/10）显示（`payrollLogic.js` L88）。
- **生产大坑（Q3 双重发放）**：管理/总部现在用 quarter_grade，如果 7-9 月绩效曾按月度法线下发过，10 月经理级会再发一次整个 Q3。安全做法：核算前把经理级 2026-Q3 系数显式录 **0.00**（0 是合法值，会走正常发放流程发 0 元，不会报 missing_coef）。

## 六、考勤模块（AttendanceController，752 行）

### 6.1 核心概念

- 考勤存 `payroll_attendance`：**一行 = 一个项目一个月**（`record_key = "ym|项目名"`），`rows` 是 JSON，按**姓名**索引每人的出勤明细。
- `FIELD_MAP`（L16-25）：Excel 表头中文名 → 入库 key 的映射，**模板下载和上传解析共用这一份**，新增列只改这里，禁止两边各写一份（注释原话，漂移过）。
- 符号口径一律以符号库（symbols.json）为准，代码里禁止硬编码符号。
- 符号别名容错 `symbolLookup`（PayrollCalculator L1060）：`√ ∨ V v ✓ ✔` 都算出勤对勾；保存符号库前 `symbolConflicts`（L1083）校验新符号不与既有别名冲突。

### 6.2 上传 upload（L96）

流程：校验 ym/项目/文件 → 项目存在性 → **已归档拒传**（L121）→ **已锁定拒传**（L124）→ `parseWorkbook`（L700）解析 → 人员校验：

- **不在本项目档案的人** → 整单拒（L140，报前 10 个名字）。
- **同项目同名多人** → 整单拒（L145）：按姓名匹配考勤会有歧义，必须先处理同名（钉钉同步后每人有唯一 ID）。
- **离职口径**（L131-138）：`status='离职'` 且 `resign_date` 早于当月 1 日的人不参与上述校验，避免离职档案挡住同名在岗人员。
- 通过校验后给每行**打标** `staff_id` + `dingtalk_userid`（L152-158），核算时优先 ID 匹配（5.1 的 findAttRow）。
- **季度绩效法人员考勤行不许带系数** `guardQuarterCoef`（L274）：系数只能走季度末月弹窗录入，考勤表带系数整单拒。
- `dry_run=1` 预演模式：只校验返回预览（人数/覆盖否/是否已有核算结果）不写库。
- 正式写入：**整表覆盖** `overwriteBlock`（L293）——新表完全替换旧块，"旧表有而新表没有的人"随之删除（2026-10-18 用户明确的口径）。

### 6.3 虚拟组（管理/案场）

- 管理/案场人员没有独立项目块，上传时用"汇总表"：`uploadVirtualGroup`（L179）逐人按当月 `categoryMap` 找到所属项目，分组后 `mergeBlock`（L257）**按人合并**进各项目考勤块。
- **任一涉及项目已归档/锁定 → 整单拒绝**，不做部分写入。
- 查看/删除同理走 `virtualGroupNames`（L63）/ `virtualGroupHasData`（L82）/ `deleteVirtualGroup`（L340），口径一致：按月分类、管理不含总部、按姓名匹配块内行。
- 管理人员虚拟组**排除总部项目**（HQ_PROJECT），总部人走 hq 线。

### 6.4 锁定、删除、导出

- `lock`（L429）：锁定 = 考勤定稿，**锁定后才能参与核算**；`status`（L27）接口里"已上传"的口径就是 locked=true。
- `delete`（L305）：删考勤写删除日志（`writeDeleteLog` L392），归档项目拒删。
- `export`（L459）：导出依赖 PayrollCalculator 注入算符号统计。
- 模板下载（routes 里 `/attendance/template`）按项目预填人员名单，同 upload 的离职口径（resignGuard）。

## 七、钉钉同步（DingtalkService + DingtalkCallbackController + DingtalkSyncCommand）

### 7.1 三条同步通路

| 通路 | 入口 | 用途 |
|---|---|---|
| 定时全量 | `php artisan dingtalk:sync`（cron 每日 02:00，withoutOverlapping + onOneServer） | 全量拉部门+人员+离职+花名册 |
| 手动全量 | POST `/api/dingtalk/sync-now`（admin）→ `syncNow` L71 | 后台按钮，带 `Cache::lock('dingtalk-sync', 600)` |
| 事件回调 | POST `/api/dingtalk/callback`（公开）→ `handle` L124 | 钉钉推送人员/部门变更，AES 加密报文 |

三道防重入：cron 的 withoutOverlapping、sync-now 的 Cache 锁、`DingtalkSyncCommand::handle`（L13）里的 **flock 文件锁**（L17-19，`storage/framework/dingtalk-sync.lock`）——flock 是兜底，不依赖 Laravel cache，防止上次跑超 240s 又起新进程。

### 7.2 DingtalkService（API 封装）

- 配置存 `sys_dingtalk_config` 表（`loadConfig` L20），`configured()` L35 判断 app_key/secret 是否齐。
- `getAccessToken`（L53）：缓存文件 `storage/app/dt_token.cache`（6000s），失败**重试 1 次**。
- `api`（L108）统一 POST，带限流退避 `rateLimitBackoff`（L143）。
- 拉数：`getAllDepartments` L168、`getAllUsers` L192（按部门递归）、`getDismissedUsers` L221 + `getDismissedUserInfos` L259（离职）、`getRosterData` L311 / `fetchRosterBatch` L371（花名册字段，批量）、`getUserDetail` L394（单人，回调用）、`getLeaveRecords` L409（请假记录，目前仅拉取未深度用）。
- `getDeptPath`（L452）拼部门全路径（历史导入的 deptFromPath 也按此格式解析）。

### 7.3 全量同步主流程 runFullSync（CallbackController L185）

1. 拉全部数据 → `syncFullSyncInTransaction`（L211）：**DB 事务包裹，任何一步失败全量回滚**（2026-09-30 修复的 P1）。
2. `syncOrgTree`（L448）同步部门树到 `org_nodes`（`dingtalk_dept_id` 关联；该列曾是生产手工列 schema drift，已补幂等迁移 2026_09_30_000001）。
3. `syncOneUser`（L538）逐人 upsert `payroll_staff`：`resolveDeptContext`（L520）定项目归属，`parseHireDate`（L513）解析入职日期。
4. `applyRosterFields`（L625）写花名册字段（薪酬档位 fixed/base、身份证、银行卡等）；金额字段经 `normalizeRosterMoney`（L772）转 float，`displayRosterRaw`（L784）保留原始展示值。
5. 离职人员标记。已修问题：回调事件 UserId 官方协议是**数组**（原来按字符串读必报错）。

### 7.4 回调 handle（L124）

- **必须先验签**（DingtalkCrypto：签名验证 + AES 解密 + 加密应答，2026-09-30 P0 修复）；未配置回调密钥时端点返回 503 拒绝。
- 事件分发：`handleUserChange` L794 → `syncOneUserByCallback` L805（单人增量）；`handleUserLeave` L863 → `markUserLeft` L874；`handleDeptChange` L891（使部门树 30 分钟缓存失效，全量拉部门树有 30min 缓存）。
- 注册地址：钉钉开发者后台填 `https://<域名>/api/dingtalk/callback`。

### 7.5 铁律

## 二十一、避坑清单（开发向）

> 运维/部署类坑在《项目交接文档.md》。这里是写代码时最容易踩的。

1. **不要在 Controller 写计算逻辑**：薪酬算法全在 PayrollCalculator，Controller 只做鉴权/参数/拦截。
2. **row_data 键恒存在**：测试断言 null 用 `assertNull`，不存在 `assertArrayNotHasKey` 的场景。
3. **重算不是"删了重插"这么简单**：归档行有快照保全（L371-409），HTTP 层还有 archivedCalcBlocker 409 二次确认。绕开任一层都可能把历史工资冲掉。
4. **0.01 差异不是 bug**：accumulatePeriodPerf 逐月先 round 再累加是既定口径，用户确认不修。不要"顺手修掉"，修了反而和已归档历史对不上。
5. **五险一金/个税的 round 顺序**是口径的一部分（分项 round 再合计），改动=改所有人的钱。
6. **`no_attendance` 不动旧结果**：当月没考勤的人，旧工资行原样保留——不是漏算，是刻意设计（L265）。
7. **月初前离职不提示**（口径A，L286）：别给他们补"缺考勤"告警。
8. **缺基数护栏**：有出勤但 fixed/base 均 0 的人会被跳过（danger），核算结果里"少了人"先想这个原因。
9. **考勤整表覆盖语义**：新上传的表里没有的人，考勤行会被删掉（L293，2026-10-18 口径）。想"追加几个人"必须传全量表。
10. **季度绩效法人员的系数不能走考勤表**（guardQuarterCoef L274），只能季度末月弹窗录。
11. **coefficient=0 是合法值**：录 0.00 走正常流程发 0 元；不录才报 missing_coef。Q3 双重发放场景靠录 0 解决。
12. **manager 表排除总部项目**；`HQ_PROJECT='物业公司总部'` 是硬编码常量（L60），公司改名要改代码。
13. **categoryMap 按月判定**：`person_type_since` 晚于核算月末 → 该月按 staff。调动次月才换类，当月跨类核算"少了人"先看这个。
14. **中文公式变量必须经 FORMULA_VAR_CN 归一化**，前端展示和后端求值用同一转换，漂移=公式取不到值=整月中止。
15. **Expr 支持函数就 7 个**：min/max/abs/round/floor/ceil/if。用户公式里出现别的函数名，保存时就该拦下。
16. **CalcRules 请求内单例缓存**：同一请求改了配置再算，读到的还是旧值。
17. **saveSnapshot 是合并不是替换**（array_replace_recursive）：删键无效，需要显式置空或改代码。
18. **GET_LOCK 在本地 SQLite 无效**：withCalcLock 的锁行为只有生产 MySQL 能复现，并发核算问题本地测不出。
19. **本地起服务必须 server_router.php**：`php artisan serve` 下 SPA 刷新 `/app/*` 404。
20. **public/app/ 不入 git**：clone/拉代码后本地必须 `npm.cmd run build` 才有前端页面；部署同理。
21. **采购"清单外未审核"不进汇总**（custom_reviewed），财务/采购数据对不上先查它。
22. **工资条是免登录公开接口**（姓名+身份证后6位）：改 PayslipController 时注意不要顺手加了登录拦截，也不要扩大返回字段（脱敏靠 payslip_config）。
23. **钉钉回调 UserId 是数组不是字符串**，按字符串读必报错（已修，别再改回去）。
24. **薪酬设置保存无服务端结构校验**（P1-1）：手改 calc_rules.json 后必须试算验证。
25. **新会话接手先读三份文档**：本文档 → 《开发记录.md》最近条目 → 《项目交接文档.md》待办与坑。

## 二十二、开发记录机制

每次完成开发或改造（含修复），**commit 前**在《开发记录.md》（同目录）末尾追加一条：

```markdown
### [日期] 版本 <git短hash> ｜ <标题>
- 功能点：
- 涉及文件：路径#L行号
- 实现思路：
- 关键技术/原因：
- 测试结果：PHPUnit x/x、Vitest x/x、构建、手动验证
- 风险/备注：
```

版本号 = git 短 hash（`git rev-parse --short HEAD`）+ 日期；项目无独立 semver。
历史记录（2026-09-29 起连续）已全部迁移至《开发记录.md》；更早历史见 `git log --oneline`。
